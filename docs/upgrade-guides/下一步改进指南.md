# CyberStrikeAI 下一步改进指南（规划版 / 仅文档）

> **文档定位**：这是给「另一套 AI 改码」用的**行动计划与改进路线图**。本文档**只做规划，不包含任何代码改动**。目标是把当前 v1.7.17 的 CyberStrikeAI 从「能跑」提升到「高性能、高安全、高体验、可维护、可扩展」的顶尖水平。
>
> **索引**：`docs/upgrade-guides/` 是本项目所有「计划 / 指南 / 评估」文档的专用目录，避免散落污染仓库根。

## 0. 一句话结论

先用一页给执行者快速判断：**这个项目 0→1 已做完（可运行、106 工具 / 31 skill 目录 / 16 agent 全部加载、I 批次落地）。当前瓶颈不是「功能缺失」，而是「单文件过大 + 前端无构建体系 + 测试覆盖不均 + 无打包/发布流程 + 若干安全/一致性残余」。** 下一步是按「风险→收益」排序，渐进式扩容，绝不推倒重来。

## 2. 根因分析（不是"堆功能"，而是「结构性」问题）

从第一性原理拆这四类病根，后面每个改进都对着病根下手：

1. **扩不动** → 单文件巨兽（Go 后端 + JS 前端），无构建 / 无模块化。
2. **不敢改** → 关键路径（executor / workflow / audit / 前端聊天）测试薄，改一处怕回归。
3. **体验糙** → 前端无打包、无 CSP、148 处 console、首屏 683KB、无 loading / 反馈统一态。
4. **发布乱** → 构建产物入仓（exe、dist）、无 release 流程、文档与运行态漂移。

## 3. 改进路线总图（版本演进，渐进不推翻）

> 原则：**每个版本只做一类可独立验收的改进**，完成后 `go build` + `go vet` + 冒烟过，再进下一版本。禁止在一次改动里混多个不相关模块。

| 目标版本 | 版本主题 | 核心目标 | 预估人力 |
|---------|---------|---------|---------|
| **v1.8 (P0/P1)** | 清障与加固 | 拆 app.go、补 workflow/audit 测试、去 console、CSP 骨架、产物入 gitignore、文档对齐 | 1–2 周 |
| **v1.9 (P1)** | 后端质量 | 拆 executor/runner、exec 路径全量单测、database 结构演进安全 | 1–2 周 |
| **v2.0 (中)** | 前端模块化 | 引入轻量构建(Vite)、chat.js 拆分、i18n 全量、组件化、Loading/错误态统一 | 2–4 周 |
| **v2.x** | 体验与安全 | CSP nonce 落地 545 处、XSS 清洗、httpOnly 会话、RBAC 复核、HITL 补强 | 按需 |
| **v3.0 (远)** | 平台化 | 多实例 / 可观测、Workflow 引擎增强、多租户、报告体系、性能基准 | 分批 |

> 执行者**不必一口气做到 v3**。建议从 v1.8 开始，逐版本推进，每版本跑通验证基线（见 §8）。

## 4. 专项改进清单（按维度，每项含：现状 → 方案 → 落地 → 验收 → 风险）

### 4.1 后端架构 / 工程化

#### A1. 拆分 `internal/app/app.go`（2424 行）—— 最高优先级
- **现状**：路由 + 服务组装 + 中间件全部在单文件，初始化顺序脆弱。
- **方案**：按「服务组」拆成多个文件（`app_routes_chat.go` / `app_routes_tool.go` / `app_routes_admin.go` / `app_deps.go` / `app_middleware.go`），**路由数量与行为不变**（spec 中 J8 已明确此目标）。用 `go build` 验证。
- **落地**：只做「移动代码 + 调整可见性」，不改变任何 handler 逻辑。路由用同一 `Register` 入口聚合。
- **验收**：`go build ./cmd/server/` 通过、`go vet ./...` 无 error、`/api/config/tools` 等关键路由冒烟与拆分前一致。
- **风险**：L2（导入环、init 顺序）。**严禁**重构 handler 内部逻辑，只拆注册。

#### A2. 拆分 `internal/security/executor.go`（1769 行）
- **现状**：命令执行安全边界单文件过大。shell exec 入口（`ExecuteTool`@292/313/325、`executeSystemCommand`@905/967-970/1116-1127）是 ShellSafeParse 已覆盖点。
- **方案**：拆 `executor.go` → `executor_build.go`（构建命令）/ `executor_run.go`（执行）/ `executor_policy.go`（HIGH_IMPACT/scope 决策）。已有 `shellsafe/highimpact/scope` 模块，只做编排拆分。
- **落地**：保持函数签名不变（spec Boundary 明确「改 executor 函数签名需 Ask first」→ 本指南**不**改签名，只拆文件）。
- **验收**：`go test ./internal/security/ -count=1` 全绿。
- **风险**：L2。

#### A3. 拆分 `internal/multiagent/runner.go`（1142 行）
- **方案**：抽 `runner_stream.go` / `runner_tool.go` / `runner_summary.go`。已有 `eino_*` 独立文件相当多，runner.go 只做入口收敛。
- **验收**：`go test ./internal/multiagent/ -count=1` 全绿 + RunDeepAgent 主链路冒烟。
- **风险**：L2（流式/重试/摘要交错，改前先跑基线测试快照）。

#### A4. 测试补齐（重点 3 个真空包）
- `internal/workflow`（24:4）→ 补齐引擎节点（start/agent/tool/condition/hitl/output/end）的进/出/异常用例。
- `internal/audit`（9:1）→ 补齐记录 / 保留 / 节流 / 脱敏 / 资源可用性全生命周期。
- `internal/knowledge`（17:6）→ 补齐 chunk / embed / 多查询 / rerank / 检索日志。
- **验收**：`go test ./internal/workflow/ ./internal/audit/ ./internal/knowledge/ -cover -count=1`，覆盖率 ≥80%。
- **风险**：L1。**改码前先跑 `go test ./... -count=1` 记录基线，杜绝新增 FAIL**。

#### A5. `internal/agent`、`internal/app` 剩余文件梳理
- 现状 agent 12:2、app 12:6。拆分后可顺带补 app 的「路由注册」单测（用 httptest 验证 `/` `/api/...` 返回 200，不依赖真实 DB）。

### 4.2 前端质量与体验（当前最明显短板）

#### F1. 引入轻量构建（Vite）做「渐进增强」，不推倒重写
- **现状**：`web/` 无构建体系，50 个 `<script>` 全局变量，`index.html` 683KB。
- **方案**：在 `web/` 引入 **Vite**（仅作打包/开发服务器/`build` 产出，**不改现有 HTML 结构**），将现有 `<script>` 改为按需 import。若执行者担心改动大，可先只做「CSS/JS 压缩 + 文件哈希 + 静态 gzip」这层，把构建体系搭起来再逐步模块化。
- **落地**：新增 `web/package.json`、`vite.config.js`、`index.html` 保留为入口。**不**大规模改 DOM / 事件 / 样式。
- **验收**：`npm run build` 产出 `dist/`，首屏体积显著下降，无打包报错，页面与原始行为一致。
- **风险**：L2。**关键**：本项目已有子集 `web/tests/e2e/`（Playwright），构建迁移后必须能继续跑冒烟。

#### F2. 拆分 `chat.js`（11188 行）→ `chat/` 模块化
- **方案**：按 spec J10 目标拆 `chat-core/ input/ render/ tools/ i18n/`。**行为不变**：DOM 结构 / 事件绑定 / i18n 键不动。
- **落地**：先建 `web/static/js/chat/` 子目录，逐步把函数迁出，每迁一块跑 `node --check` + Playwright 冒烟。
- **验收**：`node --check` 全过 + `web/tests/e2e` 冒烟三用例通过 + 对话流不回归。
- **风险**：L2。**严禁**顺手改渲染/事件逻辑。

#### F3. 清理 console（148 处）
- **方案**：抽一个 `web/static/js/logger.js`（`log.info/warn/error`，环境开关控制），把 148 处 `console.*` 替换。**不删**日志信息，只收敛到统一入口。
- **验收**：`grep -c "console\.\(log\|debug\|info\|error\)" web/static/js/*.js` → 0（或仅在 logger 内部）。
- **风险**：L1。**注意**：`console.error` 可能是错误处理的一部分，替换后需保证错误仍可见。

#### F4. CSP nonce 化（迁移 545 处 inline `onclick`）
- **背景**：`index.html` 545 处 `onclick=`，若启用 CSP nonce 需把这些迁到绑定事件（addEventListener）或改走内联 handler 的 nonce。
- **方案**（分两步，不一步到位）：
  1. 服务端在 `index.html` 渲染时注 `nonce`，CSP `script-src 'self' 'nonce-xxx'`。
  2. 把高风险、动态内联的 `onclick` 迁为 `data-*` 属性 + 事件委托（`document.addEventListener('click', ...)`）。先迁「含用户输入插值」的危险点，静态跳转可后置。
- **验收**：浏览器控制台无 CSP 违规报错；`grep -c "onclick="` 显著下降（先清零「拼接用户输入」的危险点）。需 `tls` 下用真实浏览器过一遍。
- **风险**：L2–L3（涉及所有页面）。必须**逐步**，每迁一页验证一页，回滚容易。

#### F5. Loading / 反馈 / 错误态统一（体验硬伤）
- **现状**：各页面点击是否都有 loading / 成功 / 失败反馈需逐一复核。用户明确强调「每个组件点击后是否有反馈」。
- **方案**：抽一个全局反馈组件（`toast` / `skeleton` / `empty` / `error` 四态），在各关键操作（对话发送、工具执行、审批、保存设置、删除）统一接线。
- **验收**：人工跑关键页，确认每个异步操作有 `pending → success/error` 三态，超时有提示，失败可重试。
- **风险**：L1。**用已有 `modal.js` / `notifications.js` 轮子**，不新造。

#### F6. i18n 全量 + 首屏瘦身
- 复核各巨文件是否都有中英双语；`index.html` 683KB → 断言模板拆小、懒加载非首屏模块。

### 4.3 安全（上线前底线，本就该最优先）

#### S1. 产物入 .gitignore（立即，零风险）
- `cyberstrike-ai.exe`（152MB）、`desktop/dist/`、`tmp/`、`*.db`、`logs/` 加入 `.gitignore`；从 git 移除已入库的构建产物（`git rm --cached`，**不删本地文件**）。Git 状态里它们不该出现。
- **验收**：`git status` 干净，仓库体积不含 152MB exe。

#### S2. 会话安全
- 确认 session 走 **httpOnly + Secure（TLS 下）+ SameSite=Strict** cookie；登录失败节流已在 audit 配置，复核是否全局生效。
- **验收**：登录后 DevTools 看 cookie 属性符合上述要求。

#### S3. 命令执行防御复核（executor 边界）
- 确认 shell 执行入口全部被 `ShellSafeParse` 拦截（实测：`ExecuteTool`@executor.go:292/313/325、`executeSystemCommand`@905/967-970/1116-1127）；HIGH_IMPACT 审批集（**实测 18 个破坏性工具**，`internal/security/highimpact.go`，真实阻断走 HITL 审批流程） + scope 校验在调用前触发（实测 `executor.go:208-217` scope 全链路接入已落地）。
- **验收**：`go test ./internal/security/ -count=1` 含 shellsafe **25** 条用例（实测：16 拒绝 + 9 通过）全绿；未审批高危工具返回 403 + 审计记录。

#### S4. XSS 输入净化
- 前端所有 `innerHTML` 复核，确认经 `sanitize-markdown.js`；后端输出转义。用户输入一律不允许未经净化渲染。
- **风险**：L3。发现即修，涉及安全。

#### S5. 第三方 / 依赖安全
- 复核 `go.mod` 间接依赖是否存在已知高危；npm（桌面 + web）`npm audit`。
- **验收**：`gosec ./...`（Go）+ `npm audit`（前端/桌面）无 CRITICAL。

### 4.4 性能

#### P1. 首屏体积
- `index.html` 683KB + 50 script → 经 Vite 构建后拆包 / 压缩 / 懒加载。目标首屏 `< 800KB`。

#### P2. 后端热点
- `config.go` 热应用（影响模型/知识库/C2/机器人/MCP）→ 复核是否读锁 / 复制；`database` 连接是否池化；`/api/config/tools` 是否每次重扫文件（可缓存）。
- **方案**：对纯读热路径加内存缓存（已有 `internal/cache/` 轮子，别新造），Redis 可选。**默认 memory 兜底零告警**，复用 I 批次已落地 cache。
- **验收**：压测 `go test ./... -bench` 或 ab 打 `/api/config/tools`，确认无重复磁盘 IO。

#### P3. SQLite 写入与并发
- 多实例横向扩展不天然成立（架构已注明）。可做 WAL 模式 + busy_timeout 上调，避免写锁阻塞。
- **验收**：并发对话冒烟无 `database is locked`。

### 4.5 AI / Agent 能力增强（已有很多轮子，做增量）

## 6. 执行者改码铁则（避免踩坑）

1. **绝不推倒重来**：已有轮子（Eino / gin / shellsafe / highimpact / scope / cache / blackboard / sarif / metrics / turn_limiter / i18n / modal / notifications）全部复用，只增量。
2. **一次一个不相关模块**：A1（Go 拆分）与 F2（JS 拆分）分开验收，不混。
3. **改前跑基线**：每个版本开始前 `go build ./...` + `go test ./... -count=1` 记录基线（含 FAIL 集合），改后不允许**新增** FAIL。
4. **不破坏边界**：改 executor 函数签名、RBAC 目录、schema、`local_mode` 语义 → 需 Ask-first；本文档不授权这些。
5. **不硬编码 / 不 mock**：配置全走 `config.example.yaml`（源码中 `config.yaml` 是运行态，不动；改例文同步即可）。
6. **文档同步**：任何 config/路由/结构变化，同步 `docs/` 对应篇目 + 更新本指南勾选状态。
7. **安全底线**：改动涉及认证/命令执行/用户输入/SQL → 先 security-reviewer 自查再改。

升级完成后清理，**仅清理构建残留与垃圾，不删源码头文件**：

| 清理对象 | 处理 | 说明 |
|---------|------|------|
