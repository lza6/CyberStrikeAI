三、4 项迁移设计要点

K1 coordinator（orchestrator.ts runTeam → CoordinatorRunner）

  • 两阶段：coordinator agent 调用①输出 JSON task specs（title 作为依赖 token）→ LoadSpecs 建 DAG → round-based 并发 dispatch（sem 限并发，默认 5）→ coordinator 调用②synthesis 综合全部子任务结果。
  • 解析失败走 FallbackSpecs（每 agent 一任务，goal 兜底），与参考项目一致。
  • coordinatorAgentAdapter 把 CoordinatorRunner 包装为 adk.Agent，无缝接入现有 runEinoADKAgentLoop SSE/持久化管线。

K2 title→ID 两遍扫描（loadSpecsIntoQueue → LoadSpecs）

  • Pass1：每个 spec 生成 UUID + 建 title→ID 索引（lower+trim 归一）；Pass2：dependsOn token 先试 ID 后试 title。
  • 改进参考项目 3 个缺陷：重复 title 硬报错（TS 静默覆盖）、未知 depRef 硬报错（TS 静默丢弃）、LoadSpecs 强制 ValidateDependencies（TS runTeam 从不调用 validate）。
  • Kahn 拓扑 + DFS 三色环检测。

K3 MessageBus（messaging.ts → message_bus.go）

  • Send/Broadcast/GetUnread/GetAll/MarkRead/GetConversation/Subscribe；广播不回送 sender；RWMutex + subscriber 快照在锁外回调（防自死锁）；unsubscribe 幂等。
  • worker prompt 注入消息（buildTaskPrompt）与参考项目对齐。

K4 结构化输出（structured-output.ts → extractJSON + SchemaField）

  • extractJSON 五级容错：直接解析 → ```json fence → bare fence → {..} 切片 → [..] 切片。
  • 轻量 SchemaField 校验器（string/bool/number/array/object/any，required，嵌套），错误格式化 FormatValidationIssues 可直接喂回 LLM。
  • 缺口：参考项目 validateStructuredOutput 的"校验失败→错误信息喂回 LLM 重试一次"循环未在本次实现（当前 coordinator 路径以 FallbackSpecs 兜底，功能可用）。已列为后续批次项。
