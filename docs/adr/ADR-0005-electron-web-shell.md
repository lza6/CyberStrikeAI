# ADR-0005 Electron 壳 + Web UI 主体

**状态**：accepted  
**日期**：2026-09

## 背景

平台需桌面版（小白双击即用）+ Web 访问（浏览器）。桌面外壳选型需平衡：复用 Web 资产、原生体验、打包成熟度、跨平台。

## 决策

**Electron 31.7.7 作为桌面外壳，Web UI 为界面主体，外壳增强原生能力（系统托盘/启动画面/原生对话框/单实例锁/原生菜单）。**

- 主窗 `BrowserWindow` 加载 `http://127.0.0.1:8080`（后端服务）。
- 原生外壳：托盘（显示主窗/打开Web/重启后端/退出 + 双击恢复 + 最小化气泡）、启动画面（深色+三阶段状态文案）、原生错误对话框（重试/打开日志/退出）、单实例锁（防双开端口冲突）、关窗最小化到托盘。
- 后端 `cyberstrike-ai.exe` 独立运行（也可不配桌面壳，纯命令行/服务方式跑）。

## 备选方案对比

| 方案 | 优点 | 劣势 |
|------|------|------|
| **Electron + Web UI（选定）** | 复用全部 web 资产、NSIS 成熟、原生外壳可增强 | 包体大（~165MB，含 Python runtime） |
| Tauri | 包体小 | 需 Rust 重写外壳、web 资产迁移成本 |
| Wails | Go 原生 | 不如 Electron 生态成熟、原生能力弱 |

## 后果

- **正面**：Web UI 与桌面壳共用一套前端，功能同步；托盘常驻 + 启动画面提升原生体验；单实例锁防双开。
- **负面**：包体 165MB（含 Python 3.13.5 runtime + 后端 exe + web 资源）；Electron 内存占用高于原生。
- **打包**：`electron-builder --win nsis`，`extraResources` 携带 `../cyberstrike-ai.exe` + `../web` + `../tools` + `../skills` + `../runtime` 等。
- **用户裁决**：用户明确"前端 UI 做好看点，用户就是用软件 UI"——Electron + Web UI 是体验与工程的最优解，单文件不是硬约束。
